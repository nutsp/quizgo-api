# Exam Question Blueprint Design

## Goal

ปรับหน้าจัดคำถามให้ Admin เข้าใจว่าส่วนบนคือ **โครงสร้างชุดข้อสอบ** ซึ่งกำหนดว่าส่วนต่าง ๆ ของชุดต้องมีวิชา กลุ่มคำถาม และจำนวนข้อเท่าใด ส่วนการสุ่มอัตโนมัติและการเลือกเองเป็นเพียงวิธีนำคำถามเข้าชุด โดยคำถามทุกข้อต้องอยู่ภายในโครงสร้างที่บันทึกไว้

## Product Model

- เปลี่ยนภาษาที่ผู้ใช้เห็นจาก "เงื่อนไขการจัดคำถาม" เป็น "โครงสร้างชุดข้อสอบ"
- โครงสร้างหนึ่งรายการประกอบด้วย `subject_id`, `tag_id` (ไม่บังคับ) และ `count`
- ผลรวม `count` ของทุกรายการต้องเท่ากับจำนวนข้อของชุดข้อสอบ
- `difficulty` ไม่เป็นข้อมูลรายรายการ แต่ใช้ค่าจากชุดข้อสอบทั้งชุด
- กลุ่มคำถามต้องมี `subject_id` ตรงกับวิชาของรายการ
- Admin ต้องบันทึกโครงสร้างก่อนจึงจะสุ่มหรือเลือกคำถามเองได้

## Admin Flow

1. Admin กำหนดรายการในโครงสร้างด้วยวิชา กลุ่มคำถาม และจำนวนข้อ
2. ระบบแสดงระดับความยากของชุดข้อสอบเป็นข้อมูลแบบอ่านอย่างเดียว
3. ระบบตรวจจำนวนคำถามในคลังด้วยวิชา กลุ่ม และระดับความยากของชุด
4. Admin บันทึกด้วยปุ่ม `บันทึกโครงสร้าง`
5. หลังบันทึก Admin เลือกวิธีจัดคำถามได้สองแบบ:
   - `สุ่มคำถามอัตโนมัติ` เติมคำถามที่ยังขาดในแต่ละรายการ
   - `เลือกคำถามจากคลัง` เลือกเองได้เฉพาะคำถามที่ตรงรายการและโควตาที่ยังเหลือ
6. รายการคำถามในชุดเรียงและจำกัดขอบเขตตามลำดับโครงสร้าง

## UI Copy And Layout

- หัวข้อส่วนบน: `โครงสร้างชุดข้อสอบ`
- คำอธิบาย: `กำหนดสัดส่วนวิชา กลุ่มคำถาม และจำนวนข้อที่ต้องมีในชุดนี้`
- แสดง badge อ่านอย่างเดียว: `ระดับความยาก: {ชื่อระดับ}`
- คอลัมน์: `วิชา`, `กลุ่มคำถาม`, `จำนวนข้อ`
- ปุ่มเพิ่ม: `เพิ่มส่วนของข้อสอบ`
- ปุ่มบันทึก: `บันทึกโครงสร้าง`
- สถานะ: `บันทึกโครงสร้างแล้ว` หรือ `มีการแก้ไขโครงสร้าง`
- ปุ่มสุ่ม: `สุ่มคำถามอัตโนมัติ`
- ข้อความในคลังใช้คำว่า `โครงสร้าง` แทน `เงื่อนไข`
- ส่วนคลังคำถามเป็นวิธี `เลือกคำถามเอง` และยังใช้ search/filter เพื่อค้นหาได้ แต่ checkbox เปิดใช้เฉพาะคำถามที่อยู่ในโครงสร้างและยังมีโควตา

## Backend Contract And Rules

- API rule request/response เลิกใช้ `difficulty` เป็นค่าที่ Admin กำหนดรายรายการ
- ขณะบันทึกโครงสร้าง ตรวจ capacity ด้วย `exam_set.difficulty`
- ขณะสุ่ม ใช้ `exam_set.difficulty` ร่วมกับวิชาและกลุ่มของแต่ละรายการ
- ขณะเพิ่มคำถามเอง ตรวจทั้งวิชา กลุ่ม ระดับความยากของชุด และจำนวนที่เหลือของรายการ
- Backend เป็นผู้บังคับกติกาทั้งหมด ไม่เชื่อเฉพาะการ disable บน frontend
- ข้อมูล rule เก่าที่มี difficulty จะอ่านได้ แต่ระบบจะใช้ difficulty ปัจจุบันของชุดและเขียนค่าใหม่โดยไม่พึ่งค่าราย rule

## Error Handling

- ถ้าคำถามในคลังไม่พอ แสดงจำนวนสูงสุดของรายการนั้นก่อนบันทึก
- ถ้าโครงสร้างรวมจำนวนไม่เท่าชุด ปิดปุ่มบันทึกและแสดงยอดรวม
- ถ้าเลือกคำถามที่ไม่อยู่ในโครงสร้างหรือโควตาเต็ม API ตอบ validation error ภาษาไทย
- หากเปลี่ยน difficulty ของชุดจนคำถามที่จัดไว้เดิมไม่ตรง ระบบต้องไม่อนุญาตให้เพิ่มหรือสุ่มต่อจน Admin แก้ชุดคำถามให้ตรงกับระดับใหม่

## Testing

- Unit test การใช้ difficulty จากชุดแทน difficulty ราย rule
- Unit test การสุ่มและเลือกเองถูกจำกัดด้วยวิชา กลุ่ม difficulty และโควตา
- Unit test compatibility สำหรับ rule เก่า
- Frontend lint และ production build
- ตรวจหน้า Admin ทั้ง desktop และ mobile ว่าการบันทึกโครงสร้างและสองวิธีจัดคำถามยังใช้งานได้ครบ
